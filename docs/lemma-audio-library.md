## Local pronunciation volume adjustment

Lemmas recordings now use a shared, measured playback normalization across all selected Spanish regions and voices, including the y correction; this supersedes the initial fixed +3 dB boost. Answer/completion cue levels and device-speech fallback volume are unchanged. If Web Audio is unavailable, ordinary playback is retained. When available, playback waits for activation; activation rejection/timeout uses the existing device fallback rather than silently playing an unboosted recording. Answer submission activates pronunciation before its delayed chime ends. The single-letter comparison uses the same boost and reports an error if activation fails. A fast peak compressor controls peaks above -1 dBFS after normalization. Audio nodes are disconnected when playback ends or is canceled.

The public Azure library does not return CORS headers. For boosted playback in hosted builds, `/api/pronunciation/{locale}/{clip}` streams from the fixed public Azure library; only the four Spanish locale IDs and 24-character hexadecimal MP3 filenames are accepted. It forwards Range requests and cache/media headers, never credentials or arbitrary origins. Local audio and correction clips stay same-origin. The route adds a cached hosting hop rather than modifying or regenerating recordings. This requires the hosted Worker build; a bare static build with an external audio base does not serve the proxy route.

### Measured source differences

`scripts/measure-lemma-audio-levels.py` decoded a fixed 104-clip sample locally: four headwords, four conjugations and four sentences in each of eight voices, plus eight corrected y clips. Results and SHA-256s are in `data/spanish-lemmas/audio/level-sample.json`. Measurements use unweighted RMS over 20 ms active windows (40 dB below each clip’s maximum-window RMS); these are **not LUFS or perceptual loudness ratings**.

Original headwords span -24.04 to -17.30 dBFS active RMS, forms -26.11 to -17.83, sentences -21.69 to -17.08. Matched-word spreads across voices are 4.08–6.81 dB (sentences 3.68–4.28). Corrected y spans -34.27 to -20.83 dBFS. The highest sampled source peak is -1.51 dBFS, motivating peak protection after the +3 dB gain. This scoped sample confirms real source-level differences; it is not an audit of all recordings. Source files remain unchanged; the subsequent playback normalization below is now implemented locally.

### Playback normalization (local, awaiting review)

Each newly encountered recording is fetched and decoded before playback, then measured with the same speech-active 20 ms RMS approach as the sample audit. One constant gain targets -19 dBFS active RMS, capped at ±12 dB. Signals below -60 dBFS are left unboosted. The peak compressor remains downstream. This replaces the fixed boost, rather than stacking on top of it. It approximates consistent speech level, not broadcast LUFS normalization or identical perceived loudness across timbres.

The gain for the most recent 128 clip URLs is cached in memory; decoded buffers are not retained. Initial playback requires a full fetch/decode before the media element plays; subsequent playback reuses the measured gain and normal browser HTTP caching. Cancellation aborts analysis fetches and prevents stale playback or leaked graphs. Normalization applies to headwords, forms, sentences, answer pronunciation, notes and both columns of the single-letter comparison. Feedback tones are unchanged; device synthesis fallback cannot be normalized by this path. Unsupported Web Audio retains ordinary recorded playback.

Applied to the 104-clip sample measurements, all 96 original clips reach the -19 dBFS active-RMS target before peak compression. The eight corrected y clips land between -22.27 and -19 dBFS due to the boost cap (previous spread 13.44 dB). These are predicted gain-adjusted signal levels, not a listening evaluation or measured post-compressor output. No recordings have been regenerated or overwritten.
