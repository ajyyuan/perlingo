### Learning and tests

- **Batch (10):** read ten English meanings and Spanish headwords, then type the Spanish headwords from English prompts in shuffled order.
- **Set (50):** after five batch tests, choose English meanings for all fifty Spanish words. Four distinct glosses come from the set, falling back to the deck if needed. Choice order stays stable during feedback and reload.
- **Day (300):** typed Spanish recall covers every card in the selected day, not a sample. Your days permits starting early; there is no daily lock.
- **Context review (pilot):** 50 questions cover Set 1 using its existing authored examples. Read the English translation, then complete one missing Spanish word. The required surface form can differ from the headword (somos for ser, hay for haber, al for a + el). Surrounding Spanish words show meanings on hover/focus and pronounce on click. The hidden word is absent from tooltips and pronunciation attributes until submission. Feedback restores the sentence and explains the form; supplying the headword when an inflected form is required produces a specific form-error message. The pilot is accessible from Days 1 and 2. **Full 300-word previous-day contextual reviews are planned, not implemented.** Later days explicitly state that context review is unavailable.

### Passing, mistakes and scores

Every implemented test uses the same rules. Finish the entire shuffled full pass even after a mistake. If it has misses, repair each with an unaided correct answer. A short repair queue includes up to three already encountered words so a lone miss is not simply repeated immediately; errors on those words also require repair. The last question is not immediately repeated at the start of repair when other questions exist. Finishing repair starts a new shuffled full pass, not stage completion. A stage clears only after a full pass with no errors. A perfect first pass clears directly. There are no mistake limits, mid-pass restarts, timers or uninterrupted-session requirements.

Show answer counts as a miss. After three incorrect attempts on a word, feedback offers its meaning, pattern and tip for relearning; this never changes the recorded result. The first full pass's score stays frozen through repairs and later full passes. The displayed Pass number counts full passes only; Repair is separately labeled. Local saving allows breaks at any point. “Learned” counts completed batches plus retained progress from the earlier prototype; “sets tested” requires the current set test. Neither claims long-term mastery.

Spanish answers target the deck's exact headword, normalizing case, whitespace, Unicode composition, curly apostrophes and terminal sentence punctuation. Accents and ñ remain significant. Other valid synonyms or inflected forms are not automatically accepted as the target headword.

Context answers are exact Spanish target forms from the existing examples, normalized like other typed answers. This is target-lemma practice, not unrestricted translation grading: another plausible word is not automatically recognized as equivalent. The original sentence and chunk boundaries remain unchanged; only one selected word is masked. Hover help includes the word gloss and, where different, the authored phrase meaning. Surrounding-word help is allowed scaffolding and does not mark an answer assisted; revealing the target still counts as a miss. Escape dismisses visible meaning tips; hover/focus restores them. Clicking words is also available in learning cards. No full-sentence audio is offered before answering because it would reveal the blank.

**Voice input:** all lemma answer fields (batch, day and cloze) offer Speak answer when the browser exposes SpeechRecognition or webkitSpeechRecognition. Recognition starts only after clicking, uses es-ES, fills an editable transcript and never auto-submits. Stop microphone ends capture. Rendering/navigation, manual typing, pronunciation and page hiding cancel capture; stale callbacks cannot fill a later question. Denied permissions, missing APIs, no speech and service failures retain typing. Browser speech recognition can process audio online; the UI discloses this in Voice help and the button tooltip. This is browser-provided recognition, not the Challenge app's provider integration. Search and personal notes do not have new microphone controls. Device keyboard dictation remains a fallback. Browser support and remote processing behavior follow [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).

Learning uses Up/Down or Left/Right for navigation and P for pronunciation. Tests use their actual choice buttons or the typed input and Check/Enter; arrow keys never self-grade. Help dialogs and notes retain keyboard ownership. Navigation stops pronunciation and removes overlays/listeners. Shared French Thomas preferences and quiet playback feedback are unchanged.

All 1,500 cards have lexical notes. There are **53 entries with authored sentence examples**: Set 1 plus casa, depender and música. The other 1,447 are lexical reference entries, not completed sentence lessons; no generated examples fill that gap. Generic grammar help retains the headword and meaning; authored chunk help retains its example and translation. The interface does not certify every dictionary sense or original corpus annotation.

Search links to the full reference page. `/lemmas/notes.html?set=1` has a set selector and Spanish/English search, with at most 50 matching buttons. Duplicate spellings show their grammatical category. Reference navigation does not change test progress. The original five-word prototype remains at `/lemmas/notes.html` with no set parameter.

## Implementation and reproduction

- `scripts/build-corpes-deck.py` builds `lemmas/data/deck.json` and provenance from the frozen CORPES source, dictionary extract and teaching edits. `build-lemmas.py` remains a compatibility entry point.
- `scripts/build-lemma-notes.py` builds `lemmas/data/notes.json` from that deck, dictionary genders, usage overrides and pinned form evidence. Normal builds are offline. `--form-source /path/to/es_allforms.csv` refreshes the subset only after checking the exact source hash.
- `lemmas/notes-library.js` combines generated lexical notes with `first-set-notes.js` and three reused pilot notes. Pilot concepts are namespaced so a specific explanation never replaces generic grammar for other words.
- `lemmas/note-view.js` and `note-view.css` serve both learning notes and reference pages. `notes.js` provides search/set navigation. There is no runtime AI, external generator or parser.
- Tests cover exact 1,500-ID coverage/order, source counts, sense corrections, gender/inflection exceptions, grammatical-use separation, source matches, byte-identical rebuilding, chunk reconstruction, punctuation boundaries and keyboard ownership. These checks are evidence about those properties, not a proof of all linguistic correctness.

## Source conventions

CORPES is the ranking input; Doozan supplies the pinned Wiktionary dictionary/form intermediary. Seven explicit source-label choices remain: músico→música, característico→característica, salido→salida, listo→lista, perspectivo→perspectiva, deudo→deuda, caído→caída. Their notes explain the ambiguity in More. Intereses is folded into interés without adding its count, with religioso filling the slot. Counts are not reassigned to displayed senses. No corpus-independent “true top 1,500” or 90% comprehension claim is made.

The official table is CC BY-SA 4.0 and does not identify its extraction version. The original CRLF bytes/hash are preserved. Dictionary-derived adaptations retain Wiktionary/Doozan attribution and CC BY-SA terms. Source-derived notes and edits follow the same attribution policy.

## Persistence

Saved tests include their queue, retries, first-try score, full-pass/repair mode, full-pass number, per-word failure counts, choice order, feedback and typed draft. Reload resumes the active activity. Saved state is validated against the appropriate batch/set/day.

Earlier ratings, legacy session records and completed-batch counts are preserved. The prior prototype’s flows/exams are retained under previousAssessment when migrating; old passes cannot satisfy the new perfect-pass rules. The earlier learning position is retained; an older test phase resumes at the beginning of its learning batch and does **not** become a passed active test. Old mixed-day self-rating queues are not converted to typed exams. Changing context from English meaning recall to Spanish cloze restarts that pilot; its previous session is retained under previousContext. Existing batch/day tests remain intact. The earlier `perlingo-lemmas-v1` key is neither migrated nor deleted. Identical spellings with different POS retain separate identities.

`perlingo-word-notes-v1` stores personal notes by card ID and is shared by study and the full reference view. Saves merge the latest stored object to preserve other words edited in another tab. The five-word prototype retains its separate `perlingo-word-notes-pilot-v1`. Storage failures display a visible error. There is no account sync.

## Local functional preview

1. Open `/lemmas/`, learn ten cards, then Start batch recall. Use Show answer once and answer the other nine correctly. It must finish the pass, enter Repair, then require a full Pass 2. A perfect second pass should clear the batch while retaining 9/10 as the first result.
2. Reload during repair, a full pass, feedback or an unfinished typed answer. The exact position and saved draft should resume. Repeated submission must not double-count a result.
3. Finish five batches to reach the 50-word multiple-choice set test. It uses the same perfect-pass requirement.
4. In Your days, start Day 1 test: its counter must be 1 / 300. Context review → Try pilot opens 1 / 50 with the English translation and a one-word Spanish blank. Hover/focus a surrounding word for meaning and click it to pronounce. The blank must offer neither its answer nor audio before submission.
5. Fill the Spanish blank and Check, then inspect the restored word and explanation. In a verb question, enter its infinitive instead of the required inflection to check form-error feedback. Speak answer should fill a transcript without grading; verify microphone permission, recognition quality and audible playback on the actual device. Typing must remain usable if speech fails.

These checks concern functionality; linguistic correctness is not delegated to the learner. The dataset and audit are committed; the workflow and context pilot remain local and unpublished.

## Current dictation: existing Azure broker (local)

The last bordered-button/help-only experiment was reverted. Keep the minimal text controls and compact accent picker. `recorded-dictation.js` replaces the browser Web Speech service in the study UI: click the microphone icon and speak; capture ends after 800 ms of quiet following at least 160 ms above the voice threshold, or a second click; the microphone closes before the recording is sent to `/challenge/api/speech/transcribe?provider=azure&language=es`. This reuses the existing server-side Azure configuration and shared PCM worklet without modifying challenge code or exposing keys. Audio is 16 kHz mono PCM, bounded to 12 seconds, with a 15-second transcription timeout. Azure processes audio; no target answer is sent. The editable transcript is never auto-submitted. Navigation, typing and manual playback cancel capture/pending requests and ignore stale responses.

Four new tests cover PCM submission, microphone cleanup, late permission/transcription results and provider errors. A real Azure request successfully transcribed the existing public CC BY-SA Wikimedia `LL-Q1321 (spa)-Eavqwiki-pan.wav` fixture as “Pan.”; its recorded PCM hash was checked before submission. This verifies the provider path, not live user microphone quality. The older browser-recognition module remains unused. No commit or deployment.

Automatic stopping uses PCM energy (RMS threshold 0.008), not linguistic detection. Initial silence does not trigger an early stop; the 12-second cap still applies, and silence-only recordings are not uploaded. Short pauses under 800 ms keep recording. Background noise and unusually quiet speech may affect detection. The borderless microphone has accessible start/stop/cancel labels and a subtle active background. Tests cover initial silence, brief pauses, resumed speech, automatic single submission and silence-only rejection. Live microphone timing remains a device check.
