### Learning and tests

- **Batch (10):** read ten English meanings and Spanish headwords, then type the Spanish headwords from English prompts in shuffled order.
- **Set (50):** after five batch tests, choose English meanings for all fifty Spanish words. Four distinct glosses come from the set, falling back to the deck if needed. Choice order stays stable during feedback and reload.
- **Day (300):** typed Spanish recall covers every card in the selected day, not a sample. Your days permits starting early; there is no daily lock.
- **Context review:** all five days have 300 questions each, one per lemma/POS card. Read the English translation, then complete one missing Spanish word. The required surface form can differ from the headword (somos for ser, hay for haber, primer for primero). Surrounding Spanish words show meanings on hover/focus and pronounce on click. The hidden word is absent from tooltips and pronunciation attributes until submission. Feedback restores the sentence and explains the form; supplying the headword when an inflected form is required produces a form-error message. Days 2–5 show the previous day’s review above the day’s sets. Every day also has its own review below its day test, so Day 5 remains reviewable without a sixth-day screen. Reviews are optional to start and resumable; they use the same mandatory repairs and perfect full pass as the other tests.

### Passing, mistakes and scores

Every implemented test uses the same rules. Finish the entire shuffled full pass even after a mistake. If it has misses, repair each with an unaided correct answer. A short repair queue includes up to three already encountered words so a lone miss is not simply repeated immediately; errors on those words also require repair. The last question is not immediately repeated at the start of repair when other questions exist. Finishing repair starts a new shuffled full pass, not stage completion. A stage clears only after a full pass with no errors. A perfect first pass clears directly. There are no mistake limits, mid-pass restarts, timers or uninterrupted-session requirements.

Show answer counts as a miss. After three incorrect attempts on a word, feedback offers its meaning, pattern and tip for relearning; this never changes the recorded result. The first full pass's score stays frozen through repairs and later full passes. The displayed Pass number counts full passes only; Repair is separately labeled. Local saving allows breaks at any point. “Learned” counts completed batches plus retained progress from the earlier prototype; “sets tested” requires the current set test. Neither claims long-term mastery.

Spanish answers target the deck's exact headword, normalizing case, whitespace, Unicode composition, curly apostrophes and terminal sentence punctuation. Accents and ñ remain significant. Other valid synonyms or inflected forms are not automatically accepted as the target headword.

Context answers are exact Spanish target forms from the existing examples, normalized like other typed answers. This is target-lemma practice, not unrestricted translation grading: another plausible word is not automatically recognized as equivalent. The original sentence and chunk boundaries remain unchanged; only one selected word is masked. Hover help includes the word gloss and, where different, the authored phrase meaning. Surrounding-word help is allowed scaffolding and does not mark an answer assisted; revealing the target still counts as a miss. Escape dismisses visible meaning tips; hover/focus restores them. Clicking words is also available in learning cards. No full-sentence audio is offered before answering because it would reveal the blank.

**Voice input:** all lemma answer fields (batch, day and cloze) offer Speak answer when the browser exposes SpeechRecognition or webkitSpeechRecognition. Recognition starts only after clicking, uses es-ES, fills an editable transcript and never auto-submits. Stop microphone ends capture. Rendering/navigation, manual typing, pronunciation and page hiding cancel capture; stale callbacks cannot fill a later question. Denied permissions, missing APIs, no speech and service failures retain typing. Browser speech recognition can process audio online; the UI discloses this in Voice help and the button tooltip. This is browser-provided recognition, not the Challenge app's provider integration. Search and personal notes do not have new microphone controls. Device keyboard dictation remains a fallback. Browser support and remote processing behavior follow [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).

Learning uses Up/Down or Left/Right for navigation with S for headword pronunciation and P for the first displayed example sentence. Changing tense or person makes P play that newly displayed example. Tests use their actual choice buttons or the typed input and Check/Enter; arrow keys never self-grade. Help dialogs and notes retain keyboard ownership. Navigation stops pronunciation and removes overlays/listeners. Shared French Thomas preferences and quiet playback feedback are unchanged.

- Tests cover exact 1,500-ID coverage/order, source counts, sense corrections, gender/inflection exceptions, grammatical-use separation, source matches, byte-identical rebuilding, chunk reconstruction, punctuation boundaries and keyboard ownership. These checks are evidence about those properties, not a proof of all linguistic correctness.
